## 致命问题：`vendor_library` 这条路径**永远走不到**

### 证据

`op-fused-add-rmsnorm` 的 `variants.yaml` 里有 **2 个 competitor**：

```
ref-heavy          correctness_only
lightop-rmsnormadd competitor        ← 是 vendor
aiter-norm         competitor        ← 是 vendor
fa-rms-mr2/mr4     candidate
```

但 `judge.py generate --card Plugins/ops/skills/op-fused-add-rmsnorm` 仍然输出：

```
evidence_kind = self-consistent-only
```

### 根因（我定位到了）

`engine/judge.py::_evidence_kind()` 用 **`opverify.parse_yaml`** 读 `variants.yaml`：

```python
d = parse_yaml(p.read_text(encoding="utf-8")) or {}
...
except Exception:
    return "self-consistent-only"          # ← 异常被吞
```

而 `opverify.parse_yaml` 是"YAML 安全子集"解析器，**读不了这张卡**：

```
ValueError: map/list 混用: '- name: ref-heavy'
```

`variants.yaml` 的写法是 `variants:` 下面缩进 0 的 `- name:` 列表，这个子集解析器不支持。
于是异常被 `except` 吞掉 → 对**每一张卡**都返回 `self-consistent-only`。

### 后果（这是为什么必须打回）

- `vendor_library` 永远不出现 → `claim` 第五项**永远 FAIL** → **没有任何记录能通过审计**；
- 我们造了一个"没有东西能过"的门。fail-closed 是对的，但这已经不是 fail-closed，
  是**门根本没接上**。

### 更严重的一层：静默降级

`except Exception: return "self-consistent-only"` 把**两种完全不同的情况**混成一种：

| 情况 | 应该 |
|---|---|
| 卡里真的只有参考实现（没有独立核验） | `self-consistent-only`（事实，claim 判 FAIL，正确） |
| **解析失败 / 读不到证据** | **rc=2 + 明确报错**（BUG，不许伪造结论） |

现在两者都输出 `self-consistent-only`，于是 bug 被伪装成"事实"。
**fail-closed 的正确形态是"拒绝生成"，不是"伪造一个没有证据的结论"。**
