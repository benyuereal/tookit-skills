## 二、天花板算式（本卡是校准判据的最佳载体）

```
不融合残差：读 x + 读 w + 写 y = 2*M*H*2B
融合残差  ：读 x + 读 r + 读 w + 写 y = 3*M*H*2B

prefill-8k（M=8192, H=4096）不融合：2*8192*4096*2 = 134 MB
内存地板 = 134 MB / 1724 GB/s = 78 µs
```

**字节数完全确定、无中间态、无复用** ⇒ 达成率的分母没有争议。
这是全仓库最适合校准「带宽判据」的算子。

## 三、已确立的事实

| 事实 | 机制 | 影响 |
|---|---|---|
| 融合残差是唯一真收益 | 省一次 HBM 往返（3→2 或 4→3 次） | 不融合残差的变体上限就低一截 |
| `eps` 在 sqrt 内外数值不同 | `sqrt(mean+eps)` vs `sqrt(mean)+eps` | 小值输入下可见 |
| 原地写残差会污染多变体对比 | 后跑的吃到被改的输入 | 每个变体喂独立副本 |
| 用标称 1100 做分母会误判到顶 | 已有空间被算成 87% | 一律用实测 1724 |

## 八、S3 迭代记录：SwiGLU 的 46% 缺口（Case 001 后续）

> 承接 `op-optimize/cases/001-swiglu-fused-vs-split`：那里测得融合版
> 达成率 46%（copy 峰值口径）。这里按场景表往下追两轮。

### 轮 1：vectorize-width（layout-pack）—— **证伪**

**假设**：bf16 下向量化宽度被限制在 8B 而非 16B，导致带宽上不去。

**测法**：固定 M=32768，扫 H ∈ {2048, 4096, 4097, 8192}。
若向量化宽度受限，H 不是 8 的倍数（4097）时应出现明显掉档。

| H | median | 带宽 |
|---|---|---|
| 2048 | 0.7718 ms | 522 GB/s |
| 4096 | 1.5102 ms | 533 GB/s |
| 4097 | 1.5115 ms | 533 GB/s |
| 8192 | 2.9766 ms | 541 GB/s |

**判定**：**证伪**。H=4097（非 8 倍数）与 H=4096 的带宽**完全相同**（533 vs 533）。
若向量化宽度是限制，这里应有可见落差。

```
mechanism: 向量化宽度不是瓶颈。H 从 2048 到 8192、含非 8 倍数，
           带宽稳定在 522-541 GB/s，无掉档。
           判据：同 kernel 换 H 奇偶性，带宽变化 < 2%。
```

### 轮 2：coalesce-check（gather-path）—— **假设不成立，但指向真因**

**假设**：读 `[M, 2H]` 非连续，导致有效带宽只有峰值的三成。

**测法**：同字节数（读 M*2H + 写 M*H）下对比「融合 swiglu」与「纯 copy」。
若访存模式是问题，纯 copy 应该快得多。

| 实现 | median | 带宽 |
|---|---|---|
| 融合 swiglu | 1.5272 ms | 527 GB/s |
| 纯 copy（同字节） | 0.5142 ms | **1566 GB/s** |
| | | **2.97x** |

**判定**：**假设不成立，但结论更有价值**——
访存**没有**结构性缺陷（纯 copy 同字节能到 1566 GB/s，接近 copy 峰值 1125 的
1.4 倍是因为这个 copy 只读一半写一半，实际上限更高）。

```
mechanism: 差距 2.97x 说明瓶颈不在「读 x 的访存模式」，
           而在 kernel 内部：融合 kernel 要从 [M,2H] 的两半分别读
           （gate 半与 up 半）并做跨半的乘，这打断了流式访问。
           纯 copy 是单段线性读写，能跑满带宽；
           swiglu 是「读两块 + 跨块元素乘」，天然不是单流。
           判据：同字节数下 copy 1566 GB/s vs swiglu 527 GB/s。
next:      下一轮该试「改变数据布局让 gate/up 分块连续」
           （即把 [M,2H] 拆成两个 [M,H] 独立张量喂入），
           而不是继续调 kernel 参数。
```

### 两轮小结

| 轮 | 方向 | 判定 | 机制 |
|---|---|---|---|
| 1 | vectorize-width | **证伪** | 带宽与 H 奇偶无关（533 vs 533） |
| 2 | coalesce-check | **假设不成立，指向真因** | 同字节 copy 1566 vs swiglu 527，差 2.97x，瓶颈在跨半元素乘的访存不连续 |

**这两轮的价值**：把一个含糊的「46% 还有空间」变成了具体的
「空间在数据布局，不在 kernel 参数」。下一轮该改布局，不是调参。
