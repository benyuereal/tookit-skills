# 流水线定律：主循环排布的可计算判据

> 每条 = 机制 + 判据 + 一个**会推翻它**的观测。全部来自 DCU 手写 GEMM / attention 的实测记录，
> gfx938 上成立；换设备重测。这里只放**相对倍数**，绝对耗时在 `~/.config/dcu-toolkit/kb/op-opt/`。

## 用法

写主循环**之前**，按 L0 → L4 顺次自查；写完之后，用 L5–L10 解释「为什么没到预测」。
答不出 L0 的四问就不许写代码（与 `op-roofline/references/pipeline.md` 同一套四问，这里给的是
**在库的约束下怎么排**，不是重复推导）。

## L0 四问（排队形状）

| # | 问 | 算 | 结论 |
|---|---|---|---|
| Q1 | 这份输入几个消费者？收缩维是否同一？ | 数有几个 MMA 读它 | 1 个 ⇒ global→VGPR 直喂，不进 LDS；≥2 且收缩维**正交** ⇒ 至少一侧必走 LDS（结构性，不是调参） |
| Q2 | 在途单位多大？ | `tile_k × tile_n × 字节 / 线程数` | ≤32 B/lane ⇒ 可放 VGPR；更大 ⇒ 只能 LDS，且要 × stages |
| Q3 | 气泡多宽？ | 一个 stage 内不依赖在途数据的 MMA 条数 | 气泡 < 预取延迟 ⇒ 加 buffer 只是把等待挪位置 |
| Q4 | 预算不等式 | `stages×在途单位 + 常驻 ≤ LDS/CU ÷ 驻留CTA`；`现有 + stages×每lane增量 ≤ VGPR/lane上限` | 任一不满足 ⇒ 这条流水线**不可行**，不要「先写了再看」 |

**双 GEMM 正交的反例（MLA 类）**：KV 同时是 QK 的 K（收缩 d）和 PV 的 V（收缩 k），一个 fragment
无法同时满足两侧的 8-连续要求 ⇒ 必有一侧付标量 LDS，与写法无关。照抄「B 直进 VGPR」在这是错的。

## L1 驻留（CTA/CU）比 tile 形状更早成为约束

**机制**：tile 变体几乎总在加 LDS 或加 VGPR，任何一项越过下一个驻留台阶，代价是**整机**的（第二个 CTA
藏的是整条流水线，不只是 epilogue）。

**判据**：同一个 body、只改动态 LDS 申请量（kernel 仍只读前 N 字节，输出必须 bit-identical），量出
「掉一档驻留」的价。本项目实测 +27.5%（另一个 kernel 上同类实验是 +68%）——**同一档的价跨 kernel 不可外推，
外推只能当上界**。

**反例**：`__launch_bounds__(threads, 1)` **不是**探针——aicc 只抬寄存器上限，两个 device body 字节
相同、VGPR 不变，两次运行都在 2 CTA/CU。零效应不能读成「测到了一 CTA」。

**推论**：任何「用驻留换更大 tile」的设计，必须先从自己的结构里买回这一档的钱，否则别立项。

## L2 每 barrier 的工作量是主杠杆，但它有价格

**机制**：一个 barrier 锁住共享同一 SIMD 的两个 wave，barrier 的**次数**不是成本，**锁住的宽度**才是。
同一条指令流在 4-wave CTA 上便宜得多。

**判据**：在**等驻留**前提下把每个 barrier 覆盖的 k 宽度翻倍（例如 32 → 64 条 MMA/wave），实测收益
是 +10.5% 量级；但只要它多要的 LDS 挤掉一档驻留，净收益立刻转负（本项目 −14%）。

**一句话**：先算 L4 的不等式，再谈 cadence。

## L3 预取深度不是延迟杠杆

**机制**：多 slot / 更深 lead 只改变「等待发生在哪」，不改变流的**自身时间**。

**判据**：4-slot B 预取、barrier 等「除最新四个外全部到齐」——数值 bit-identical、0 spill、同驻留，
仍然 +2.2% 慢。⇒ 该侧暴露的不是延迟，是带宽时间；继续加深度是空转。

**反例（真正的延迟杠杆在哪）**：A 读的问题不是字节量而是**等待链**——把读量砍半只换回该侧 234 µs 里的
37 µs（16%）。**不要用更少/更窄的读去攻它**，要改的是「谁在等谁」。

## L4 寄存器是生命周期，不是容量

**机制**：两个小 buffer 顺序复用同一批 VGPR = 生命周期分段；合并成一个大 buffer = 生命周期全程重叠。

**判据**：合并后活集合 ≥ 每线程上限 ⇒ 保证溢出。本项目合并 4 路切分实测 spill 30、慢 2.12×，
与「大 tile 更高效」的直觉相反。

**配套反例（编译器陷阱）**：用**运行时** slot 索引（`B_l[slot]`）会让本地数组落到 scratch——
144 B/lane 溢出、VGPR 反降、**又慢又算错**。两路展开 + 字面量 stage/slot 即可 0 spill。

## L5 删掉一段指令 ≠ 省它占的比例

**机制**：占比高的单元可能已经被重叠吃掉，或者是 preload/流水填充。

**判据**：删掉每线程 32 条 mul 的那一块，只换回 1.1%；另一处删掉后**反而慢 1.1%**（它是预取）。
**只用消融实测，不用占比推算。**

## L6 调度变体删同步，必须单独过数值门

**机制**：删掉 barrier 前的 `vmcnt(0)` 让墙钟快 15 µs，但 copy 的 global→LDS 写会与下一块的 LDS 读
竞争 ⇒ 输出 NaN（本项目 76444/67108864 元素不符）。

**判据**：**时序收益 + 数值失败 = 失败**。这一类变体必须同时过数值门，只有计时门会把它放出去。

## L7 账本里被误标的行会骗你两轮

**机制**：把「内存/等待/barrier 全关」的那一行当硬件地板，而那行里**还留着 store 与 barrier** ⇒ 凭空
多出 0.19 ms 的「未解释开销」，于是花一整轮去攻 barrier 和 MMA ILP，两件事都不是瓶颈。

**判据**：地板行必须逐项声明**关了什么**；每关一项单独记一行。「未解释残差」出现时，先怀疑账本漏项，
再怀疑硬件。

## L8 常数能推出物理不可能，就是常数错

**判据**：任何占用率/CTA 数算出来是 0 个 CTA、>100%、或与实测矛盾时，**先判常数错**。
本项目 `VF_LIMIT=65536`（非 768-VGPR 模式的值）把 2 CTA/CU 算成 1 CTA/CU，据此下的整条结论是错的；
反验：另一个内核 172 VGPR × 512 线程，用这个常数会算出 **0** 个 CTA。

## L9 小 M 的绑定是「CTA 数 × 每 CTA 固定开销」，不是 tile

**机制**：M≤8 时每步必读整份权重、每 CTA 只有极短的循环，算力与带宽都只有个位数百分比 ⇒ 真正的
杠杆是 persistent（减少 CTA 数与 prologue），或把跨 query 的复用并进 GEMM 的 N 维。

**判据（persistent 的前提）**：常驻数据**不能吃掉 shared**——为让 Q 常驻而花 shared 把 2 CTA/CU 打到 1，
净效果比非 persistent 还慢 1.9×；放寄存器也救不回来。**persistent 成立 ⇔ L4 不等式不变。**

## L10 一个数只能有一个分母

三种「带宽利用率」之间差 20 个百分点：流式读峰值 / 该布局的纯载入上限 / 该 shape 自己的 pattern 速率。
报百分比必须同句写分母来源与测法；**同 shape 的两个达成率并存 ⇒ 其中一个是错的，先查分母再用。**
