# 作战宪章：每轮优化开场必填

> 为什么需要它：没有宪章的优化循环会**无限试错**——本项目一轮做过 43 条判死只落地 1 个已知收益，
> 其中 3 次实验的失败本可以用一次演算避免。
> 宪章的作用是**把「问人」提前到开场一次**，之后不再打断。

---

## 0. 一句话目标

> 例：把稀疏 MLA 在 S=128 / 320k 的 op_call 从 X µs 降到 Y µs

## 1. 口径（少写一行就不许开跑）

| 项 | 值 |
|---|---|
| 目标形状 / S / ctx | |
| H / topk / pool | |
| 测量单位 | `op_call`（单次调用）还是 `step`（含全部层） |
| 基线怎么来 | 每轮现测，还是引用某次 run 的产物（要写路径） |
| 精度判据 | contract 的哪一条（`vs_fp32_ref` / `variant_vs_variant`） |

> **口径不全时 `allowed = [gather_evidence]`**，任何优化动作都不许做。

## 2. 预算

- 最多 **N** 个实验（一次编译+一次测量算 1 个）
- 最多 **T** 小时
- 超出前必须先回演算，不许"再试一次看看"

## 3. 停止条件（命中任一条即停，写报告）

| 条件 | 判据 |
|---|---|
| **a. 方向封死** | 同一方向连续 **2 次结构性判死**（编译期不可行 / 资源预算必然爆 / 输出不 bit-exact） |
| **b. 局部最优** | 所有可试类别都有 ≥1 条判死，且**没有一条是「没测明白」** |
| **c. 预算耗尽** | 实验数或时间到上限 |
| **d. 空转熔断** | 连续 **3 轮**没有任何状态变化（没跑实验 / 没新增判死） |

命中后**必须**产出：`该设计点局部最优` 或 `需要人拍方向`，并附证据链（哪些判死、覆盖了哪些类别）。

## 4. 升级契约：只有这四件事要问人

1. **改目标形状 / 口径 / 精度判据**
2. **动生产文件、删公共产物、改 `contract.yaml`**
3. **预算超支**（要加实验或加时间）
4. **需要外部信息**（别的实现的源码、trace、别人的实测）

除此之外一律自主：选候选、写变体、跑测量、判死、记账。

## 5. 记录纪律

- 每条判死**必须写机制**（为什么不行、被什么挡住、什么条件下会反转）。只写「试过，慢」等于没写。
- 每条结论带 `verdict`（`confirmed` / `plausible`）与 `anchor`（`file:line` / run 目录 / trace id）。
- 硬件常数只有被**具名 probe** 复现过才算 `confirmed`。
- **完成判定不靠模型自述**：候选的 `done_when` 命令返回 0 才允许 `adopted`（见 `loop.py verify`）。

## 6. 开场检查清单（打印出来逐条打勾）

```
[ ] 口径 6 行填满
[ ] 预算写死
[ ] 停止条件确认
[ ] 已跑 pipeline.md 的四问（新设计必需）
[ ] 已查 isa-census.md 的指令面（选实现必需）
[ ] 基线本轮现测过（不是引用历史数字）
[ ] refuted 清单读过（避免重开）
```

> 这份宪章本身也可以写进 run 目录：`runs/op-optimize/<run>/charter.md`，作为该轮的"前提"留档。
