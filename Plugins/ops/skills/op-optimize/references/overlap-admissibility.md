# 重叠结论的准入条件

> 这一条解决的不是「怎么测重叠」，是「什么样的重叠结论才算数」。
> 它是**方法类**判据，不是实现类——写在这里，由脚本强制。

## 为什么需要它

「重叠」类结论最容易出两种错：

1. **把噪声当重叠**：两侧耗时量级差太远，小的一侧被大的一侧的抖动淹没
2. **把「两边各自变快了」当重叠**：只看总时间下降，不看是否真交错

本项目两次踩过第 1 种：阶段 3 用 1GB copy(1.6ms) 配 8192 GEMM(27.5ms)，
同机器两次跑出 92% 与 0%；阶段 4 对照组用 512MB D2H(17.4ms) 配
routed(0.31ms)，窗口占 1.8%，测出 18.4%——全是噪声。

**同一个坑两次，说明教训只写成文档是不够的，必须固化成检查。**

## 准入条件（硬）

### A1 两侧耗时比必须落在 [0.2, 5]

```
ratio = min(t_a, t_b) / max(t_a, t_b)
ratio < 0.2  ⇒ 拒绝出结论（报 WAIVER 也不够，先调量级）
ratio ∈ [0.2, 5] ⇒ 可以出
```

**为什么是 0.2**：窗口 = min(t_a, t_b)。当 ratio=0.2 时，窗口是总量的 1/5，
而实际测量噪声通常在 1-2%，此时信噪比 ≥10，结论可信。ratio 低于 0.2 时
信噪比迅速恶化——实测 ratio=0.018 时，同一配置两次结果差 5 倍。

### A2 必须有对照组

「A+B 不重叠」这种阴性结论，必须同时给出一个**已知能重叠**的对照
（如 D2H + GEMM），证明测量方法本身有效。

否则无法区分「真的不重叠」和「测量方法测不出重叠」。

### A3 分母用 min，不用 (串行和 - max)

```
重叠度 = (串行和 - 并行) / min(t_a, t_b)
```

物理上「最多能隐藏多少」就是较小那一侧的全部耗时。
用 (串行和 - max) 会在串行测量因干扰偏大时算出 >100%（实测 145%），
那不是「重叠得更好」，是分母本身不稳定。

### A4 结论要区分三种情形

| 重叠度 | 判定 | 含义 |
|---|---|---|
| ≥ 50% | 真重叠 | 小的一侧基本被隐藏 |
| 5%-50% | 部分重叠 | 有收益但不完全 |
| < 5% | 无重叠 | 两边各跑各的（同引擎争用） |

## WAIVER 的边界

确实无法让两侧等量级时（例如待测的一侧本身就是固定的 0.3 ms 小 kernel，
而唯一能重叠的 partner 是 GB 级 D2H），可以写 WAIVER，但**必须**说明：

```yaml
waiver:
  reason: "为什么量级不匹配无法避免"
  noise_argument: "为什么在这个量级差下噪声不影响结论"
  cross_check: "用什么独立证据佐证（如 PMC 计数、kernel 时间线）"
```

**没有这三项，WAIVER 不成立。** 光写「量级确实不同」不算理由。

## 脚本里的实现

`cases/002-moe-pipeline/stage3_overlap.py` 与 `stage4_shared.py` 都有
`assert_window(ta, tb)`：ratio 越界直接 `sys.exit(2)`，不产出 result.json。
