# dcu-skill-on-device-verification — README

## 定位
DCU 技能库**真机验证方法论**（跨技能、横切流程）：把技能按「需要什么资源才能验证」分成可验证性五分层（A 只读环境 / B 编译运行 / C 重型推理多卡 / D 故障排查 / E 文档方法论），挑便宜的优先实跑技能自带的脚本，并对照 SKILL.md 里写死的基线数字判断准确性。不是某次验证任务的记录，而是可重复的验证流程。

## 何时用
- 用户问「dcu skills 里哪些内容能在设备上验证一下 / 看技能是否生效、内容是否准确」
- 需要系统性核对一批技能的准确性（而非单个技能排障）
- 评估技能库「地基」（环境/编译层）是否可信

不用：单个技能的具体操作（进对应技能）；给技能新增经验（那是各技能自己的事）。

## 核心
- **可验证性分层 A–E**：决定验证顺序与资源投入（先 Tier A 最便宜，再挑 Tier B 代表性 1-2 个验证编译链路；C/D/E 不建议在「验技能」阶段碰）。
- **验证循环**：加载技能正文 → 找「可执行产物 + 基线数值」→ 真机实跑 → 对照基线 → 有出入先定性（通用差异=改主体 / 版本特定=补对照表保留旧版 / 技能错=修正 / 环境差异=只记录）→ 回填。
- **双版本对照定性**：同时起技能来源版本 + 一个更新版本镜像，对同一断言各跑一遍，区分「通用演进」vs「版本特定」（如 vLLM `--device` 两版都无 vs SGLang `is_dcu`→`is_hcu`）。
- **已验证基线**（<device-A> 设备累计 17 技能全生效，覆盖环境/编译/通信/部署/性能/包源/引擎全链路），详见 `references/bw150-gfx936-verification-2026-08.md`。

## 与 dcu-skill-router 的关系
本 skill 是「验证技能库质量」的横切流程；dcu-skill-router 是「用技能做事」的入口。两者互补。

## 使用
用户要求扫描/去设备验证 DCU 技能时，加载本 SKILL.md（含可验证性分层 + 验证循环 + 双版本对照定性 + 真机/容器执行环境 + Pitfalls），按层挑代表技能实跑对照。
