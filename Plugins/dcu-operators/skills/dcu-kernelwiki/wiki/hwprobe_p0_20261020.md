# P0 底层硬件探测（hwprobe）方法与硬件资源事实

## 1. 方法：单一 HIP 程序取"属性 + microbench"
`hwprobe.hip`（单文件，约 130 行；四台机器留档（内部路径略））：
1. `hipGetDeviceProperties`（v1 结构体）全字段输出：name / gcnArchName / totalGlobalMem / memoryClockRate / memoryBusWidth / clockRate / multiProcessorCount / maxThreadsPerMultiProcessor / maxThreadsPerBlock / regsPerBlock / maxSharedMemoryPerMultiProcessor(LDS) / l2CacheSize
2. Bench：1GB float4 D2D copy / 纯读 / 纯写 / 纯读 scalar（向量化对照）/ 2000 空 kernel launch 延迟 / LDS 带宽（64 block×256 thr×32KB 读写混合）
3. 输出逐行 key=value，便于入库

编译：`hipcc -O3 --offload-arch=<gfx> hwprobe.hip -o hwprobe`
运行：`HIP_VISIBLE_DEVICES=<空闲卡> timeout 240 ./hwprobe`（先 `hy-smi` 确认卡空闲，不碰他人服务）

## 2. 三宿主编译/运行配方（glibc 差异，2026-10-20 实测）
| 宿主类型 | 示例机 | 做法 |
|---|---|---|
| 新 glibc（≥2.35，Ubuntu 22.04） | <device-A>（BW150） | 宿主直跑：hipcc 需加 `-isystem /usr/include/c++/11 -isystem /usr/include/x86_64-linux-gnu/c++/11`（`--gcc-toolchain=/usr` 实测无效） |
| 旧 glibc（2.28，Kylin/CentOS7 系） | <device-C>（K100-AI）、<device-B>（BW100）、<device-D>（BW1100） | 宿主跑不了 DTK-26.04 任何程序（runtime libgalaxyhip 要 GLIBC_2.29；conda 只有 libstdc++ 无 glibc）→ **特权容器**（见下）+ 本机已有 dtk26.04 镜像；容器内原生编译（Ubuntu22.04 系镜像 glibc 2.35），或用新 glibc 机（<device-A>）交叉编译的成品直接容器内运行 |

- 特权容器最小集：`docker run --rm --network none --privileged --security-opt seccomp=unconfined --device /dev/kfd --device /dev/dri -v /opt/hyhal:/opt/hyhal:ro -v <dir>:<dir>`
- ⚠ **docker 默认 seccomp 会弄坏 DTK 工具链**：hipcc 的 clang driver spawn 子进程报 EPERM abort；HIP runtime 初始化 segfault（libgalaxyhip 内空指针，宿主 dmesg 可查）→ `--privileged --security-opt seccomp=unconfined` 是硬要求
- 交叉编译可行且已验证：新 glibc 宿主（<device-A>）同款 DTK-26.04 编译任意 gfx 目标（gfx928 成品上 <device-C> 容器跑通；gfx936 成品上 <device-B> 容器跑通）
- 容器内 DTK 路径自发现：`find / -maxdepth 5 -name libgalaxyhip.so.5` 定位 runtime 库目录进 LD_LIBRARY_PATH；hipcc 用 `find / -maxdepth 4 -name hipcc | grep -v cmake | head -1`

## 3. 硬件资源事实（与 SKILL.md 硬件作用域表互补；性能数字在 perf-cases）
| 卡(机) | gfx | CU | 线程/CU | L1 | L2 | LDS/CU | boost | HBM | PwrCap |
|---|---|---|---|---|---|---|---|---|---|
| K100-AI (<device-C>) | gfx928 | 120 | 2560(40 wave) | 16KB | 8MB | 64KB | 1400MHz | 64GB (875MHz×4096bit) | 400W |
| BW150 (<device-A>) | gfx936 | 80 | 2560(40 wave) | 32KB | 8MB | 64KB | 1400MHz | 64GB (1800MHz×4096bit) | 600W |
| BW100 (<device-B>) | gfx936 | 64 | 2560(40 wave) | 32KB | 8MB | 64KB | 1300MHz | 64GB (1800MHz×4096bit) | 400W |
| BW1100 (<device-D>) | gfx938 | 64 | 2560(40 wave) | 未测 | 8MB | 64KB | 1350MHz | 144GB | 800W |

- 三代（928/936/938）**L2 均为 8MB**（四卡实测）；L1 代际不同（928=16KB、936=32KB、938 待补）
- BW1100 的 HIP `memoryBusWidth` 报 256（异常值），勿用它算理论 HBM 带宽
- <device-D> 机 bw1100 镜像内 rocminfo 缺 `libhsa-runtime64.so.1`（DTK 树内无此库）跑不了 → gfx938 的 L1/SIMD-per-CU/Shader Engines 等 rocminfo 字段暂缺；HIP 结构体字段已全
- K100-AI 每 block 512 线程是 XDZS2025 实践值，**硬件 max = 1024 线程/block**（maxThreadsPerBlock 实测）

## 4. DCU hipDeviceProp_t 字段名（DTK-26.04，与 ROCm 命名不同）
- v1（`hipGetDeviceProperties`）：`multiProcessorCount`（非 multiprocessors）、`maxSharedMemoryPerMultiProcessor`（非 sharedMemPerMultiprocessor）、有 `l2CacheSize` / `gcnArchName`、**无 `regsPerThread`**
- v2（`hipGetDeviceProp_t_v2`）：另有 `uuid` / `regsPerMultiprocessor` / `maxBlocksPerMultiProcessor` / `reservedSharedMemPerBlock` / `clusterLaunch` / `memoryPoolsSupported`
- 运行时库名 `libgalaxyhip.so.5`（DTK-26.04；<device-C> 镜像在 /opt/dtk/lib，<device-A> 宿主在 /opt/dtk/hip/lib，<device-D> 镜像在 /opt/dtk/lib）

## 5. rocminfo 纪律（2026-10-20 实测）
- 物理机 rocminfo 必须用与驱动配套的新版 DTK：DTK-25.04.2 在新驱动宿主（<device-C>）只枚举 CPU agent（DCU 不可见）
- <device-C>（glibc 2.28 宿主）跑 DTK-26.04 rocminfo 需 conda libstdc++ 6.0.34 作 LD_LIBRARY_PATH shim（缺 GLIBCXX_3.4.26）——**仅 rocminfo 等轻量工具可 shim，HIP 程序不行**（要 glibc ≥2.29）
