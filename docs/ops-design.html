03 / OPERATOR CARD

算子卡：固定七件套

点左边任意一行看说明。★ 是决定判定结果的三份文件。

Plugins/ops/skills/op-sparse-mla/
SKILL.md
这张卡怎么用：适用场景、变体选择、常见坑。
contract.yaml★
opverify.py 唯一事实来源。数学定义、形状、dtype、布局约束、容差、不变量。容差必须带实测依据。
variants.yaml★
所有实现路径并列记录。status 状态机 draft→measured→tuned→at_floor；padding_support 与 mutates_inputs 必填。
candidates.yaml
可证伪候选清单，由 op-constrain 生成。
shapes/
具体档位：S / ctx / topk / H。
bench/
微基准脚本 + PMC 数据，统一走 opbench.py。
tests/
正确性 / 不变量 / 布局测试，opverify 直接执行。
ledger.md★
档位 × 变体 × 相对值 × 状态。每行能回到一次可复跑的 run；作废结论划掉写理由。
references/
算法论文、上游实现、历史讨论。

contract.yaml：把「算对」变成验收对象

没有契约时，「优化通过了」= 模型自己觉得。

tolerance: vs_fp32_ref: { max_abs: 2.0e-3, cosine: 0.9999 } variant_vs_variant: { max_abs: 3.0e-3 } # 实测 1.95e-3 invariants: - determinism # bit_exact ×5 - index_permutation_invariance - split_invariance

variants.yaml：所有实现并列

哪条能改、哪条受限于生产安装树、哪条只做参考，必须写清楚。

variants: - id: prod-vllm # 生产 AOT ASM status: active - id: tilelang # 可改 status: usable - id: tilelang-prefetch status: usable

ledger.md：只写可复跑的东西

只写档位/变体/相对值/状态。绝对耗时写环境专属知识库。作废结论保留——那是最有价值的反面证据。

04 / RUNTIME

它是怎么跑起来的

一次请求从进来到沉淀，经过 12 站。每一站只干一件事，交出固定格式的文件；下一站不认聊天记录，只认文件。

01
人提问
「sparse-mla 这次改动算不算通过？」——此时还没有任何技能被加载。
↓ 自然语言请求
02
router路由 / 转发
两条真实机制：dcu-skill-router（`SKILL.md` 里的七域路由表，覆盖约 140 个技能）+ dcu-dispatcher（`intent_classifier.py` 程序化意图分类，管编码类四意图）。
算子优化 → ops 域（op-sparse-mla / op-gate / op-optimize 工作流）；模型适配 → dcu-inference 域（model-deploy / infer-optimize 工作流）。
→ skill 集合 + 工作流选择
↓ 选中的技能
03
orchestrator规划：出计划state: init
读 workflow 契约：节点、依赖、并行度、哪些节点要人批。建 run 目录，并用 workflow_state.py init 生成状态文件。
→ 节点 DAG + runs/op-optimize/ + workflow-state.json
↓ 节点计划
04
op-profile采集（只读）state: mark done
按 op-bench 口径计时，采 PMC 证据，产出热点。不改任何代码。
→ profile/result.json（含环境指纹）
↓ 结果 + 指纹
05
verify_evidence门禁：只信文件state: verify
核对 path 存在、指纹字段齐全且非占位；workflow_state.py verify 重算产物 sha256，内容变了就降级 stale。缺一项，链条就停。
→ pass / stop（stale 节点必须重跑）
↓ pass
06
op-roofline推天花板state: mark done
判 memory/compute bound，算出理论天花板与地板达成率。
→ roofline/result.json
↓ cost_bound
07
op-constrain硬约束state: mark done
把判定映射成 allowed_actions。越界方案（memory bound 下仍调 tile）直接退回。
→ candidates.yaml
↓ 候选清单
08
人⏸ 审批 ①
改代码 / 编译 / 注入属高风险。YAML 里写死 proceed: ask，agent 必须停下等你批准。
→ 人工决策
↓ 批准
09
op-optimize实施state: mark done
在允许集合内单点改动，opverify 自检，保留可一键回退的 diff。一轮只动一个点。
→ optimize/result.json
↓ 改动 + 自检
10
op-validate判定：四闸四档state: mark done
verdict 只认 opverify 的 --json 输出。ACCEPTED 才放行；INCONCLUSIVE 补采样重判。
→ validate/result.json（verdict）
↓ ACCEPTED
11
人⏸ 审批 ②
写持久知识属高风险：一旦进台账，就会被下一个人复用。
→ 人工决策
↓ 批准
12
op-distill沉淀 → 复用state: finish
只收 ACCEPTED，写五段台账。下次路由先检索台账，直接给出上次结论与已证伪方向。
→ kb/op-opt/*.md → 下次秒回

数据接力：一站传一站

runs/op-optimize/ ├── workflow-state.json ← 节点状态 + 产物 sha256 ├── profile/result.json ← 指纹 + 热点 ├── roofline/result.json ← 天花板 ├── constrain/candidates.yaml ├── optimize/result.json ← diff + 自检 ├── validate/result.json ← verdict └── distill/… → 知识库

交接契约：path + fingerprint（gfx/dtk/image/model）+ status。上一站没产出或指纹对不上，下一站不启动。

三个角色

分工写死在流程里，不靠自觉。

Agent

理解意图、出计划、写代码、总结——不决定数字

Script

计时、判定、校验指纹——所有事实的来源

人

只在两处审批：改代码前 / 写知识前

状态轨：workflow-state.json 管什么

workflow_state.py init → 建状态文件，登记节点清单 mark → 节点完成时写 status + 产物 {sha256, size, mtime} verify → 重算哈希；内容变了 → 降级 stale（退出码非零） inspect → 查看进度（人类可读 / --json） finish → 收尾门禁，三选一不过就拒绝

收尾门禁：MISSING_ROOFLINE_EVIDENCE（缺 roofline 证据）· UNRESOLVED_CEILING（measured > ceiling×1.5）· UNFINISHED_NODES（还有节点没跑完）。

两个价值：断点续跑——跑到一半断了不用从头来；产物不留白——结果被改过会被判 stale，强制重跑。

实现：Plugins/dcu-core/skills/dcu-orchestrator/scripts/workflow_state.py（纯标准库，带文件锁 + 原子写）

05

口径

## 已证伪 - 热工作集口径不能用于跨实现比站位：索引池缩到 2.4MB 全在 L2， flash_mla 快 1.83×、tilelang 仅 1.03× → 系统性低估 memory-bound 一方 - 前置 -1 布局：tilelang 按块首计数截断循环，前置哨兵会静默算错 ## 口径 - 计时: opbench 多轮中位数 + MAD · 频率档: 实测 sclk 1150MHz
